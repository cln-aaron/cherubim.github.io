How it works

From a URL to a proven report, unattended.

No agents, no appliances, no scoping call. Point it at a target and it runs the engagement the way an operator would, then hands you the evidence.

1

Set the target

A URL, a hostname, or a wildcard for a whole domain. Pick single-target or subdomain discovery.

2

Launch

The engagement starts immediately and works through all 22 phases, chaining weak signals into real impact.

3

Watch it work

Follow tool calls, agent reasoning, HTTP traffic and phase transitions live. Nothing runs in a black box.

4

Act on proof

Each finding lands with the exploit that worked, a CVSS score, CWE and OWASP mapping, and the remediation.

5

Hand it over

Export a report or send a signed link to the engineer who owns the fix. No rewriting for a second audience.

6

Re-run on release

Wire it into CI or a schedule and re-test every deploy, so you catch a regression the moment it ships.

Exploit validation

If it can't land the exploit, it isn't a finding.

Scanners flag patterns and leave you to sort the real from the noise. Cherubim does the part that actually costs your team time: it attempts the exploit, reproduces it in an isolated sandbox, and captures the request and response that worked.

What reaches your queue is already confirmed. There's no "informational" pile to wade through, and no argument in triage about whether something is exploitable, because the proof is attached.

  • Working proof of concept on every finding, so the fix conversation starts at "how", not "is this real".
  • No regex false positives. Detection is confirmed by execution, not by matching a signature.
  • CVSS, CWE and OWASP mapped on each issue, with concrete remediation.
  • Safe by design. Non-destructive payloads and rate-limit awareness keep production up.

Data handling

Your vulnerabilities stay yours.

A list of your live, exploitable weaknesses is about as sensitive as data gets. Isolation, encryption and control over that data are defaults here, not upsells.

  • Tenant isolation at the row level, so one customer's findings are never visible to another.
  • Encrypted in transit on every request and response.
  • Never used for training. Your engagements don't feed a model.
  • Export and delete on your terms, with retention under your control.
Engagement boundariesenforced
  • Authorized scope only. An engagement runs against the target you set, nothing adjacent.
  • Non-destructive. Proof is captured; data is never altered or removed.
  • Rate-aware. Traffic respects limits so production stays healthy.
Questions

Straight answers.

How is this different from a vulnerability scanner?

A scanner flags patterns and hands you a list to triage. Cherubim attempts the exploit and only reports what it can reproduce, with the request and response that proved it. If it can't land the exploit, it doesn't become a finding.

Is it safe to run against production?

Yes. It uses non-destructive payloads and respects rate limits, so it's built to run against live systems without causing an outage or corrupting data.

How long does an engagement take?

A single target usually completes in 10 to 30 minutes across all 22 phases. Wildcard mode enumerates and tests subdomains, so it runs longer depending on the surface it finds.

Can it run in a pipeline?

Yes. A REST API, a GitHub app and CI/CD hooks let you gate a merge or a release on verified findings above a severity threshold you set, so the build only breaks on exploitable issues.
